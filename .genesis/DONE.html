What This Project Does

An AI-powered PR review agent that understands full PR context (title, description, changed files, commit history, code around changes, tests, repo structure, conventions, linked issues) and produces evidence-based, prioritized findings across 22 review dimensions: bug detection, security review, test coverage analysis, regression analysis, code quality, performance analysis, API/contract compatibility, dependency analysis, documentation impact, repository-aware review, change-risk assessment, finding prioritization with severity levels, confidence scoring, duplicate detection, multi-agent specialized review, verification/evidence loops, and PR-level executive summaries.

AI Components

  • LLM-based code understanding and reasoning
  • Multi-agent architecture with specialized reviewers (Bug, Security, Test, Perf, API, Quality agents)
  • Finding merger with deduplication and severity ranking
  • Evidence-based verification loops to reduce false positives
  • Repository pattern learning from accepted/rejected findings

Distributed Components

  • Context Builder — aggregates PR metadata and code context
  • Specialized review agents — parallel analysis pipelines
  • Finding Merger — deduplication and ranking
  • CI/CD integration — webhooks, static analysis, test runners

Trust Boundary

Network-facing: receives webhooks from GitHub/GitLab/Bitbucket, processes external PR data, and posts comments back. Must handle untrusted input safely (SQL injection, XSS, secrets in PRs, etc.).

Section 2 — Definition of Done

Phase Gate: Phase 2 → Production

Functional Requirements — All must pass

  • ☑ Receives webhook from GitHub and extracts PR context (title, description, files, commits)
  • ☑ Builds full code context (changed lines + surrounding code + tests + repo structure)
  • ☑ Runs all 6 specialized review agents in parallel and returns findings
  • ☑ Each finding includes: severity, confidence, category, evidence, impact, suggested fix
  • ☑ Finding merger deduplicates and ranks findings by severity
  • ☑ Produces PR-level executive summary with risk assessment and recommendation
  • ☑ Posts review as PR comment (or saves to file for local mode)

Quality Requirements — All must pass

  • ☑ False positive rate < 10% (validated against 10 known-good PRs)
  • ☑ Security findings include exploit path explanation
  • ☑ All outbound calls (LLM, GitHub API) have explicit timeouts
  • ☑ Untrusted webhook input is validated against schema before processing
  • ☑ No domain logic depends on specific web framework (clean architecture)
  • ☑ Test coverage ≥ 80% on core review pipeline

Integration Requirements — All must pass

  • ☑ GitHub webhook receiver works with ngrok or production URL
  • ☑ CI pipeline runs tests and lints on every push
  • ☑ Review completes within 5 minutes for a 50-file PR
  • ☑ Graceful degradation when LLM API is unavailable (queue + retry)
